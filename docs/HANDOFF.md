## ۱. راه‌اندازی روی کامپیوتر خودتان

پیش‌نیازها: **Node.js 22+**، **pnpm 10** (با `corepack enable`)، Git. (Docker فقط برای تست ایمیج لازم است.)

```bash
git clone https://github.com/dash000meyti/GoodInTeam.git   # اگر قبلاً کلون کرده‌اید: git fetch --all
cd GoodInTeam
git switch dev                 # شاخه کاری اصلی
corepack enable
pnpm install
cp .env.example .env.local     # برای dev کافی است؛ برای production حتماً APP_SECRET واقعی بگذارید
pnpm db:reset && pnpm db:seed  # دیتابیس نمونه (data/app.db)
pnpm dev                       # http://localhost:3000
```

ورودهای نمونه (رمز همه: `goodteam-demo-pass`):

| نقش           | ایمیل                    |
| ------------- | ------------------------ |
| مالک          | `owner@goodteam.local`   |
| عضو تیم       | `sara@goodteam.local`    |
| مشتری (پرتال) | `client@acme-academy.ir` |

دستورهای مهم: `pnpm check` (lint + typecheck + تست واحد)، `pnpm build`، `pnpm test:e2e` (تست‌های
مرورگری Playwright روی سرور در حال اجرا با دادهٔ نمونه؛ آدرس با `BASE_URL`)، `pnpm db:generate` (بعد از
تغییر schema)، `node scripts/shots.mjs` (اسکرین‌شات خودکار fa/en، روشن/تیره، موبایل، `--full` برای کل
صفحه). Playwright از Chromium خودش استفاده می‌کند؛ اگر نصب نیست: `pnpm exec playwright install chromium`
یا مسیر یک Chromium محلی را با `CHROMIUM_PATH` بدهید.

> ⚠️ سرور را فقط با پورتش متوقف کنید: `lsof -ti tcp:3000 -sTCP:LISTEN | xargs kill`. بدون
> `-sTCP:LISTEN` برنامه‌هایی هم که فقط به آن پورت وصل‌اند (مرورگر، اپ Claude) بسته می‌شوند.

> ⚠️ در production (`pnpm start` یا Docker) اگر `APP_SECRET` خالی یا همان مقدار نمونه
> (`change-me-…`) باشد، سرور عمداً بالا نمی‌آید. یک مقدار تصادفی ۳۲+ کاراکتری بسازید:
> `openssl rand -base64 48`.

**کارایی (build تولیدی، موبایل ۳۹۰px، CPU چهار برابر کند + شبکهٔ 4G):**

عنصر LCP خود تیتر صفحه است. جزئیات و روش اندازه‌گیری در `os-shell.md` بخش «Performance budget».

## ۳. تأیید مالک — ✅ همه تأیید شد (۲۶ آبان ۱۴۰۵)

هر هفت مورد زیر همان‌طور که پیاده شده‌اند تأیید شدند. فهرست برای سابقه می‌ماند؛ تغییر هر کدام از این
به بعد یک درخواست تازه است (راه تغییر هر مورد در خودش نوشته شده):

1. **شکل فارسی نام برند: «گودین تیم».** گزینه‌های دیگر: «گوداین تیم» یا فقط لاتین (Good In Team).
   «گود این» با فاصله رد شده (خوانده می‌شود «گودِ این»). تغییرش یک جست‌وجو و جایگزینی مستند است
   (حدود ۴۵ جا در ۱۴ فایل؛ فهرست دقیق در `docs/brand.md` بخش «Changing the Persian form»)، به‌اضافهٔ
   مقدار ذخیره‌شده در production (پنل → تنظیمات → پروفایل).
2. **راهنمای فشرده روی گوشی و تبلت (D21، ریسک ۱۲).** زیر ۱۰۲۴px و روی صفحه‌های لمسی، آواتار به هر بخش
   نمی‌رود: بالای داک می‌ماند، با رسیدن به بخش تازه علامت «!» نشان می‌دهد و فقط با لمس توضیح می‌دهد (به‌جز
   یک سلام اول). دلیل: حباب در هر بخش بخش بزرگی از صفحهٔ گوشی را می‌پوشاند. جایگزین آماده (فاز ۲):
   «چیپ کوتاه» یک‌خطی بالای آواتار برای ۲٫۵ ثانیه.
3. **آواتار و لحن اول‌شخص (ریسک ۱۳).** آواتار با انتخاب شما (مدل M3، ۲۶ آبان ۱۴۰۵) دوباره کشیده شد: یک
   صفحه‌نمایش تیره در قاب لوگو با دو چشم زرد و دست‌وپای کوتاه؛ در منوبار فقط آیکون ۱۰×۱۰ بدون پا. جمله‌های
   راهنما از زبان شما و اول‌شخص‌اند («من…»).
4. **۱۳ آیکون پیکسلی** (کاتالوگ، بخش Brand). آیکون `more` (یک مربع زرد از چهار) ۲۵٪ رنگ زرد دارد، بالاتر
   از قاعدهٔ ≤۲۰٪.
5. **بودجهٔ CSS.** هفت فایل CSS جدید روی هم ۹٫۲KB gzip (۴۵٫۸KB فشرده) شده‌اند در برابر سقف ۶KB / ۲۲KB.
   حذف قانون‌های مرده و تکراری انجام شد؛ پایین‌تر آوردنش بدون ساده کردن ظاهر ممکن نیست. یا سقف را
   بپذیرید، یا یک دور ساده‌سازی طراحی (مثلاً نوار تب موبایل یا انیمیشن‌های راهنما) را بخواهید.
6. **جاوااسکریپت پنل** +۱۸KB gzip شده (سقف spec: +۱۰KB) به‌خاطر Radix Menubar، داک، Launchpad و مرکز
   کنترل. همان تصمیم: پذیرش یا یک دور کوچک‌سازی.
7. **کنتراست رنگ‌های غیرپیش‌فرض.** متن سفید روی دکمه‌های رنگ سبز، فیروزه‌ای و قرمز ۳٫۱ تا ۳٫۷ است (فقط
   برای متن درشت AA). پیش‌فرض زرد و رنگ‌های بنفش و آبی سالم‌اند؛ نارنجی اصلاح شد. پیشنهاد: یا متن تیره
   روی این سه رنگ، یا نگه داشتن همین.

**تازه برای دیدن (فاز ۲):** ۱۷ آیکون پیکسلی داک پنل و ارقام پیکسلی فارسی را در پنل ← Design system ←
Brand ببینید؛ ضعیف‌ترها به نظر سازنده: `design-system`، `docs` و «۴». راهنمای سایت را هم می‌توانید از
تنظیمات ← پروفایل سایت خاموش کنید.

## ۴. استقرار (تصمیم با شما)

شاخه `main` در ۲۶ آبان ۱۴۰۵ از `dev` ساخته شد (`3220912`): CI سبز، و workflow «Release» ایمیج Docker را
ساخت و در GHCR گذاشت (`ghcr.io/dash000meyti/goodinteam:latest`). هنوز سروری وصل نیست، پس چیزی منتشر
نشده (کار `deploy` فقط با متغیر `DEPLOY_WEBHOOK_ENABLED=true` اجرا می‌شود). **هرگز `dev` را بدون دستور
صریح شما روی `main` نبرید** (`main` خودکار ایمیج می‌سازد و منتشر می‌کند). برای اتصال سرور/پلتفرم (VPS با
Docker Compose، یا Coolify/Dokploy — `docs/deployment.md`):

1. Volume دائمی روی `/data`، پورت ۳۰۰۰، health check روی `/api/health`.
2. متغیرها: `APP_SECRET` (تصادفی، ۳۲+ کاراکتر، بعد از راه‌اندازی **هرگز** عوض نشود)،
   `NEXT_PUBLIC_SITE_URL=https://دامنه‌شما`، `APP_TIMEZONE=Asia/Tehran`، و پشت reverse proxy
   (Caddy/Traefik/Coolify) حتماً `TRUST_PROXY=xff:1` (پشت Cloudflare: `cloudflare`).
3. بعد از اولین اجرا در پنل → تنظیمات → پروفایل، **نام برند ذخیره‌شده (`profile.brandName`)** را به
   شکل نهایی فارسی و انگلیسی برسانید؛ تغییر پیش‌فرض کد فقط روی نصب خالی اثر دارد.
4. در پنل → محتوا، **برند هر خدمت** را بررسی کنید (نقشهٔ فعلی: وب/موبایل/هوش مصنوعی → گودین کد،
   مشاوره → گودین تیم، طراحی → گودین استودیو). سرویس نمونهٔ `svc-design` فقط برای دمو است.
5. در GitHub → Settings → Variables متغیر `SITE_URL` (دامنهٔ نهایی) را بگذارید؛ ایمیج فعلی با
   `http://localhost:3000` ساخته شده و آدرس canonical و نقشه سایت را از همین می‌گیرد. برای استقرار خودکار
   `DEPLOY_WEBHOOK_ENABLED=true` و secret `DEPLOY_WEBHOOK_URL` را هم اضافه کنید.
6. هر بار به Claude بگویید «`dev` را روی `main` ببر» تا نسخهٔ تازه ساخته و منتشر شود.

## ۵. نکته‌های کوچک شناخته‌شده

- `/p/<توکن نامعتبر>`، slugهای ناموجود و دورهٔ ناموجود انگلیسی (`/en/learn/<x>`) داخل صفحات stream‌شده
  بدنهٔ «پیدا نشد» با کد ۲۰۰ و `noindex` برمی‌گردانند (محدودیت streaming؛ برای سئو مشکلی ندارد).
- ولاگ‌های بدون کاور، تصویر بندانگشتی یوتیوب را بعد از لود صفحه می‌گیرند؛ در شبکه‌هایی که یوتیوب
  مسدود است فقط پس‌زمینه تیره دیده می‌شود — برای ولاگ‌ها کاور آپلود کنید.
- داده نمونه بعضی مطالب (ولاگ، دوره Next.js) فقط فارسی است؛ نسخه انگلیسی‌شان ۴۰۴ می‌دهد.
- در حالت dev اگر بعد از `pnpm build` صفحه مدام خودش را بارگذاری کرد: `rm -rf .next/dev` و dev را
  دوباره اجرا کنید.
- شاخه‌های قدیمی روی GitHub (`wip/*`، `claude/adoring-wright-5hrh98`) ادغام شده‌اند و می‌توان حذفشان کرد.
