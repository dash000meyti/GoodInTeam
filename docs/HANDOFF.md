# وضعیت پروژه و ادامه کار

> به‌روز تا ۲۳ مهر ۱۴۰۵ (۱۵ اکتبر ۲۰۲۶). این فایل را اول بخوانید، بعد `AGENTS.md`.

## ۱. راه‌اندازی روی کامپیوتر خودتان

پیش‌نیازها: **Node.js 22+**، **pnpm 10** (با `corepack enable`)، Git. (Docker فقط برای تست ایمیج لازم است.)

```bash
git clone https://github.com/dash000meyti/GoodInTeam.git   # اگر قبلاً کلون کرده‌اید: git fetch --all
cd GoodInTeam
git switch dev                 # شاخه کاری اصلی
corepack enable
pnpm install
cp .env.example .env.local     # برای dev کافی است؛ برای production حتماً APP_SECRET واقعی بگذارید
pnpm db:reset && pnpm db:seed  # دیتابیس نمونه (data/app.db)
pnpm dev                       # http://localhost:3000
```

ورودهای نمونه (رمز همه: `goodteam-demo-pass`):

| نقش           | ایمیل                    |
| ------------- | ------------------------ |
| مالک          | `owner@goodteam.local`   |
| عضو تیم       | `sara@goodteam.local`    |
| مشتری (پرتال) | `client@acme-academy.ir` |

دستورهای مهم: `pnpm check` (lint + typecheck + تست واحد)، `pnpm build`، `pnpm test:e2e` (تست مرورگری
Playwright روی سرور در حال اجرا)، `pnpm db:generate` (بعد از تغییر schema)، `node scripts/shots.mjs`
(اسکرین‌شات خودکار fa/en، روشن/تیره، موبایل). اگر Chromium نصب نیست: `pnpm exec playwright install chromium`
یا مسیر یک Chromium محلی را با `CHROMIUM_PATH` بدهید.

> ⚠️ در production (`pnpm start` یا Docker) اگر `APP_SECRET` خالی یا همان مقدار نمونه
> (`change-me-…`) باشد، سرور عمداً بالا نمی‌آید. یک مقدار تصادفی ۳۲+ کاراکتری بسازید:
> `openssl rand -base64 48`.

### یافته‌های بازبینی کد — همه رفع شده‌اند ✅

- **امنیت:** XSS از طریق لینک‌های Markdown؛ open redirect در `next`؛ قفل شدن حساب مالک با
  rate limit؛ IP قابل جعل (`TRUST_PROXY`)؛ race در `/setup`؛ کوکی Secure یکسان؛ چک `APP_SECRET`
  هنگام بوت؛ لو نرفتن خطای DB در `/api/health`؛ کدهای خطای درست در MCP/REST؛ rate limit API بر اساس
  توکن تأییدشده؛ ۴۰۴ برای مسیرهای ناشناخته (`/de/…`، `/x.png`)؛ محدودیت فیلدهای فاکتور برای مشتری.
- **درستی داده:** `partial()` در zod 4 دیگر فیلدها را ریست نمی‌کند؛ پاک کردن تاریخ/بودجه/نرخ؛
  ارقام فارسی و جداکننده هزارگان در ورودی عدد؛ اعتبارسنجی کد ارز؛ «عقب‌افتاده» فقط بعد از پایان روز؛
  رخدادهای تکراری در داشبورد؛ `UNTIL` در RRULE بر اساس منطقه زمانی اپ، `WKST` و ثانیه‌های DTSTART.
- **دسترسی:** پرتال مشتری ساعت/پیشرفت را فقط با اجازه نشان می‌دهد؛ اعضا فقط پروژه‌های خودشان را در
  داشبورد می‌بینند و فیلدهای مدیریتی (بودجه، نرخ، توکن اشتراک) را نمی‌گیرند.
- **UI:** حذف drizzle از باندل کلاینت (−۱۷۰KB gzip)؛ حفظ مقادیر فرم بعد از خطای سرور؛ اتصال
  label/hint/error به کنترل‌ها؛ تأیید حذف مایلستون؛ نام‌های دسترسی و ترجمه‌ها؛ کنتراست سایدبار؛ ⌘K با
  کیبورد فارسی؛ بدون پرش سایدبار جمع‌شده؛ تب‌های پروژه در موبایل؛ سوییچ زبان با بارگذاری کامل صفحه.

## ۳. کارهای باقی‌مانده

### الف) استقرار (تصمیم با شما)

شاخه `main` هنوز روی GitHub ساخته نشده و سروری وصل نیست. وقتی سرور/پلتفرم را انتخاب کردید
(VPS با Docker Compose، یا Coolify/Dokploy — `docs/deployment.md`):

1. Volume دائمی روی `/data`، پورت ۳۰۰۰، health check روی `/api/health`.
2. متغیرها: `APP_SECRET` (تصادفی، ۳۲+ کاراکتر، بعد از راه‌اندازی **هرگز** عوض نشود)،
   `NEXT_PUBLIC_SITE_URL=https://دامنه‌شما`، `APP_TIMEZONE=Asia/Tehran`، و پشت reverse proxy
   (Caddy/Traefik/Coolify) حتماً `TRUST_PROXY=xff:1` (پشت Cloudflare: `cloudflare`).
3. به Claude بگویید «`dev` را روی `main` ببر» تا `main` ساخته شود و استقرار خودکار انجام شود.

### ب) نکته‌های کوچک شناخته‌شده

- `/p/<توکن نامعتبر>` و slugهای ناموجود داخل صفحات stream‌شده، بدنه «پیدا نشد» با کد ۲۰۰ و `noindex`
  برمی‌گردانند (محدودیت streaming؛ برای سئو مشکلی ندارد).
- ولاگ‌های بدون کاور، تصویر بندانگشتی یوتیوب را بعد از لود صفحه می‌گیرند؛ در شبکه‌هایی که یوتیوب
  مسدود است فقط پس‌زمینه تیره دیده می‌شود — برای ولاگ‌ها کاور آپلود کنید.
- داده نمونه بعضی مطالب (ولاگ، دوره Next.js) فقط فارسی است؛ نسخه انگلیسی‌شان ۴۰۴ می‌دهد.
- شاخه‌های قدیمی روی GitHub (`wip/*`، `claude/adoring-wright-5hrh98`) ادغام شده‌اند و می‌توان حذفشان کرد.

### ج) فاز ۲

فهرست پیشنهادها در `docs/roadmap.md` (فاز ۲): اعلان تلگرام/ایمیل، PWA و تایمر یک‌لمسی، ربات تلگرام،
